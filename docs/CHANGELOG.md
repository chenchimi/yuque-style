# 更新日志（全文）

README 里只保留近期版本的摘要，**每条 ≤2 行**。完整正文如下。

- **v0.7.0** 修复「语雀端给知识库下的分组改名后，增量同步不会更新本地文件夹名」（v0.6.9 及以前一直如此）。根因：增量判定只比对文档自身的 `updated_at`，而分组（TOC 里的 TITLE 节点）改名**不会改动组内任何文档的这个字段**，于是整组命中「跳过未变化」，本地目录名永远停在旧的那个——文档正文没变，但目录结构已经变了。修法：同步记录新增 `folder` 字段存「上次同步时由 TOC 推出的分组」，每轮同步与本轮 TOC 比对，不一致就把文件整体搬到新分组下；**正文没变就不重新拉取**，只是移动文件。两个踩过的坑与两处防误伤：新增的分组目录必须先 `ensureFolder` 建好再 `vault.rename`（该 API 不会自动创建父目录，否则整组报 `ENOENT`——正是升级后第一次实测撞到的）；为了不与「用户自己在本地改目录名」冲突，`folder` 只记录**语雀侧**的分组（本地重命名走 `applyRename`，只改 `path` 不动它），并且只在「路径结尾确实对得上旧分组、且段边界落在 `/` 上」时才搬，对不上就尊重用户、原样不动；升级前写下的旧记录没有分组历史，先按当前本地结构认账并记下，所以**升级后第一次同步就撞上改名也能正确跟随**，不必白等一轮。配套：只有分组改名、一篇正文都不用写时，也会刷新「XX 目录.md」索引页（内容没变则不写，免得平白刷新文件时间）

- **v0.6.9** 把「全隐藏时收起整块属性面板」的规则从 `styles.css` 挪进运行时注入的 `<style>`：实测只隐藏属性行会留下空的「笔记属性」标题与「+ 添加笔记属性」按钮，而 `styles.css` 里那条规则没能生效（Obsidian 未重新读取插件样式文件），注入那份则是同一套已被验证可用的机制。规则现在点名容器、行容器、标题、添加按钮四个选择器（`display: none !important`），即使某个版本容器类名不同，空壳也留不下来；编辑与阅读两种模式同时生效
- **v0.6.8** 属性全隐藏时把**整块属性面板一起收起**：此前五个属性行虽然没了，Obsidian 仍会画出容器本身，文档顶部只剩一个「笔记属性」标题和「+ 添加笔记属性」按钮，看着像没生效（由 `hidesWholePanel()` 判定并给 `body` 挂类，`styles.css` 收容器）。设置界面里的五个 toggles 收成**一个「笔记属性」下拉**：每项标注「已显示 / 已隐藏」，点一下即切换，另有「全部显示」「全部隐藏」两个快捷项，说明里带上「当前：隐藏 N / 5 个」的统计
- **v0.6.7** 修复「笔记属性：语雀ID 关掉没反应」。Obsidian 建属性行时执行 `setAttr("data-property-key", key.toLowerCase())`——键名被**强制转小写**，所以 `语雀ID` 在 DOM 里是 `语雀id`，拿原始键名匹配永远不中（纯中文键不受影响，只有含 ASCII 的键会踩到，恰好吃掉这一个）。现在生成选择器时按同样规则转小写。另外把**「文档头信息」变成总开关**：关掉它时五个笔记属性一并隐藏，逐个开关同时置灰并在说明里提示
- **v0.6.6** 修复「补齐文档属性」补不回被清理掉的属性。此前它只补 `语雀ID` / 时间 / 标签，**`标题` 与 `来源` 不在补写清单里**；更要命的是属性被整体清理过的文件**连前言区都没有**，而实现只认「已有前言区」，于是永远补不回来（全库文档都曾是这个状态）。现在两处都修好：补齐清单加上 `标题`（取列表接口的标题）与 `来源`（由同步记录的 `namespace/slug` 还原，与同步写入时逐字节一致），并对没有前言区的文件**整块新建**后接在正文前；改写后照旧回写同步指纹，避免下次同步误判为「本地被改过」
- **v0.6.5** 属性从「能不能写」改成「显不显示」：**取缔 v0.6.1 引入的「文档属性」开关**（及配套的「移除文档属性」命令、关闭时的清理弹窗），属性一律写入文件——数据层不做开关，免得文档头、双链索引、Dataview 因开关状态而时有时无。新增五个**逐个**的显示开关 `笔记属性：标题 / 来源 / 语雀ID / 语雀创建时间 / 语雀更新时间`（默认全部显示，位于阅读分组、紧跟「文档头信息」），实现方式是运行时生成 CSS 隐藏属性面板里的对应行，**中文键与旧英文键都覆盖**（未迁移的存量文档同样立即生效）。边界：源码模式下仍会看到 YAML 原文，属性对其它插件依然可读
- **v0.6.4** 新增设置项**「文字颜色」**：语雀彩色文字怎么落到 Markdown——**不输出颜色（默认，纯文本）**／转 `==高亮==`／保留 `<span style="color:...">`。原因是 Obsidian 的**实时预览不渲染内联 HTML**，只要正文里写了 span，编辑模式下就一定会看见源码；默认不输出，编辑与阅读两种模式都干净。命令「清理默认文字颜色」更名「清理文字颜色标记」，清理口径跟随该设置（保留颜色时只解默认色，否则连真正选过的颜色一起解），高亮背景始终不动。实测规模：默认灰 span 涉及 390+ 篇，真正有颜色的只占 36 篇、约 100 处
- **v0.6.3** 关掉「文档属性」开关时不再只影响以后：会弹窗问一句**是否把已写入文档里的语雀属性一并清掉**（默认建议清理，也可选「只关闭」）。清理只删本插件写入的键（中文键与旧英文键），正文和用户自己添加的属性一律不动，前言区因此变空时整块删掉；改写后回写同步记录指纹，避免下次同步误判为「本地被改过」。同时新增命令「语雀同步：移除文档属性」供随时单独执行；清掉后重新打开开关并跑「补齐文档属性」即可补回
- **v0.6.2** 修复「正文被默认文字颜色包成 `<span style="color:...">` 噪声」：默认色判断原先只认纯黑 `rgb(0,0,0)`，而语雀的默认正文色是 `#4D4D4D`、标题色是 `#4F4F4F`，于是逐段被包上 span（实测 390+ 篇中招，有的单篇 151 个），实时预览下还会直接显示成源码；现在这两色与纯黑一样不再输出。新增命令「语雀同步：清理默认文字颜色」，**不调 API** 就地清理已同步的存量文档（平衡扫描解包，嵌套时不会把后段文字并进彩色 span 里；真正选过的颜色与 `==高亮==` 背景不动），并回写同步记录的指纹以免下次同步误判为「本地被改过」
- **v0.6.1** 文档属性全面中文化：键名从 `yuque_created_at` 这类英文改为 `标题` / `来源` / `语雀ID` / `语雀创建时间` / `语雀更新时间` / `语雀标签`，Obsidian「属性」面板不再显示被截断的英文键；新增设置项**「文档属性」可整体开关**，关闭后同步不再写入前言区（文档头退回文件名、双链索引退回同步记录，功能都不失效）；读取一律中文键优先、旧英文键回退，**存量文档不迁移也能正常用**；命令「补齐文档元数据」更名为「补齐文档属性」，跑一次即可把旧键名就地迁移（保持字段顺序，中文键已存在时删掉旧行以免出现两份同名属性）
- **v0.6.0** 修复文档头「创建于」显示的其实是**本地文件创建时间**（也就是首次同步下来的那天）这一错误信息，改为读取语雀的真实创建时间，缺失就不显示、绝不退回本地时间；补上 `yuque_id` / `yuque_created_at` / `yuque_tags` 落盘（此前 API 已返回 `created_at` 却没存）；修复标签区读取同步从不写入的 `tags` 键、导致该区域从上线起一直为空；新增命令「补齐文档元数据」，只调文档列表接口（每 100 篇 1 次请求）给存量文档补字段，并顺带产出语雀端已不存在的孤儿文档清单（仅报告，不删除）
- **v0.5.1** 修复「语雀文档链接从未被转换为本地双链」——转换条件里的 namespace 比对恒不成立，功能自上线起就没生效过；解析范围从「仅同知识库」扩展到**全 vault**（跨库引用也能转），映射表改用每篇文档 frontmatter 的 `source` 建索引；新增命令「语雀同步：重建内部链接」，纯本地修复已同步的历史文档，不消耗 API 配额
- **v0.5.0** 删除自绘浮动目录（改用 Obsidian 原生大纲）；排版收口覆盖实时预览（图片圆角居中限高、语雀式引用、行内代码样式、h1 去下划线、行高 1.75 与段间距、**宽表格横向滚动**）；文档头不再重复正文标题；工具栏新增链接与文字颜色，并支持表格工具条；斜杠菜单补齐 10 种卡片、折叠块（折叠 callout，实测 `<details>` 内部不解析 Markdown）、目录块、两栏对比，代码块改为关键词唤起；**修复目录名含空格时图片链接退化成普通文本**（链接目标未转义）；栏宽上限提到 1600px 并新增「跟随窗口宽度」开关；编辑模式下标题与行内标题强制左对齐
