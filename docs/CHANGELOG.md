# 更新日志（全文）

- **v0.9.3** 体验与结构双升级（行为无破坏，406 例既有测试全部原样通过）。**新功能**：① **启动时自动同步**（新设置项，默认关）——Obsidian 启动 15 秒后自动执行一次「同步全部任务」，复用手动同步的进度弹窗、停止按钮与既有的预算/熔断兜底，不另起静默通道：自动触发更要让人看得见它在消耗配额；无 Token 或无任务时静默跳过（条件不满足不是故障）。② **清理孤儿文档副本**（新命令）——「补齐文档属性」每趟都产出孤儿清单却从不处理，本命令用文档列表接口（每 100 篇 1 次请求，不拉正文）比对出语雀端已删除的本地副本，弹窗逐条列出、确认后移入**系统回收站**（可恢复）并清掉对应同步记录；判定收在纯函数 `pickOrphans`（`src/yuque/orphan.ts`），关键防线是「列表拉取失败的库不下孤儿结论」——漏判只是少删一篇，误删可就找不回来了。③ **文件浏览器同步标记**（新设置项，默认开）——语雀同步文档的行尾显示小圆点（`src/yuque/explorer-sync.ts`），与隐藏图片文件夹同一套 MutationObserver 防抖扫描；「本地是否有改动」不做（要逐篇读文件，挂在扫描器上代价不成比例），冲突提示仍由同步过程的备份与日志负责。④ **图片灯箱**——阅读模式点击正文图片全屏放大，点击任意处或 Esc 关闭（`src/lightbox.ts`），事件委托挂 document 而非逐图绑监听（预览内容会随渲染重建）。⑤ **高频格式动作注册为命令**——加粗/斜体/删除线/下划线/高亮/行内代码/清除格式/三种列表/引用/代码块/分割线共 13 条命令（`src/editor-commands.ts`），可在「设置 → 快捷键」绑定；动作内核与顶栏同为 `rich-actions.ts` 一份，不会出现第三套实现。**重构（只搬代码不改行为，每步以构建 + 全量测试为门槛）**：约 520 行的 `syncTask` 拆为 8 个阶段函数（取数兜底 / 目标确定 / 增量判定 / 拉取转换 / 内链 / 图片 / 写入 / 索引页），`sync.ts` 其余部分未动；891 行的 `ui.ts` 拆出 `sync-modal.ts`（进度弹窗）、`task-modal.ts`（添加任务向导约 500 行）、`diagnose.ts`（诊断），原导出路径保持 re-export 兼容；815 行的 `main.ts` 把设置页拆到 `settings-tab.ts`；`api.ts` 合并 `rawRequest`/`getRaw` 两段重复的 requestUrl 调用为 `send()`，响应类型收紧（`YuqueUser`、`UrlResponse`、泛型 `requestJson<T>`），全库 7 处 `any` 清零。核实后放弃的一项：`lake.ts` 的 strip 函数族疑似「三层重复」，实读为两层收敛 + 一行委托，无实质重复，不做人为改动。**测试**：406 → **442**（新增 api 直测 17 例——节流 400ms、429 两步短探测→熔断只发 2 次请求、401/404/500 归因、翻页终止、remainingFromHeader；orphan 6 例、explorer-sync 5 例、lightbox 8 例）；`tests/mocks/obsidian.ts` 补 `Modal` 基类替身（否则 `extends Modal` 的模块在 Node 下加载即抛）与可注入的 `requestUrl` 假实现。`npm test` 442 例全绿，`npm run build` 类型检查通过

- **v0.9.2** 配额观测与请求预算——让同步在配额下**可预期地跑完**，而不是撞墙才知道。**起因**：用户提供了语雀官方文档《[如何使用接口](https://www.yuque.com/yuque/developer/openapi)》，其中明确记载「每小时最多 5000 次、每秒 100 次」并称响应头会返回 `X-RateLimit-Limit` / `X-RateLimit-Remaining`。这与本仓库此前的结论（`docs/free-account-alternatives.md` §2.2、README 与 `ui.ts` 的 UI 文案都写死了「语雀不返回 `X-RateLimit-*`」）**直接冲突**——而复查代码后发现，那条结论**从未被真正验证过**：`captureRate()` 只读 `via` / `x-oauth-scopes` / `retry-after` 三个头，全库**没有任何一处**打印过完整响应头，那句 UI 文案是硬编码的字面量。**观测层**（本次第一优先）：`YuqueRateInfo` 增加 `limit` / `remaining` / `reset` 并按响应头如实捕获；「诊断」命令新增 `dumpHeaders()`，把**完整响应头**打进控制台、摘要（`via` / 三个配额头）进弹窗；`explainStatus()` 改写为按「有无配额头 + `via` 是否带 `[429]`」给出**应用层 / 网关层**的归因，不再对用户下未经验证的断言，`describeQuota()` 也从「单一实测值」改为**区分官方记载与本机实测**两件事（`YUQUE_QUOTA_DOCUMENTED`）。**记账**：新增纯逻辑模块 `src/yuque/rate.ts`——每次响应都计入「本小时请求数」（跨小时归零），每次 429 连同等小时累计请求数写入**本地时间线**（保留最近 50 条），取历次最小值作**观测门槛**，×0.8 作为**建议预算**只在诊断里展示、**绝不自动启用**；观测量在 `main.ts` 按 2 秒节流落盘（429 例外，立即落盘），卸载前补写一次。**预算层**：新增设置项「每次同步请求上限」（高级分组，默认 `0 = 自动`：能读到 `X-RateLimit-Remaining` 就按剩余额度走，读不到就不限、只保留 429 熔断）；判定收在纯函数 `decideBudget()`（`api.ts` 新增 `requestCount` 与 `remainingFromHeader`），多个判据同时存在时**取最严的那个**。**任务边界软停**：检查点放在「已算出本任务还需拉多少篇、且一篇正文都还没拉」的位置，因此保证「**要么这个库完整同步、要么它根本不开始**」——不会出现目录索引页只覆盖一半、正文只写了一半的半拉子状态（判据可精确计算：每篇正文 1 次请求，TOC 与文档列表的那 2 次此时已花掉、无法回避）。**停止原因显式化**：`SyncTaskOutcome` 由 `{ quotaExhausted, remainingDocs }` 改为 `{ stop: done | quota | budget | aborted, remainingDocs }`——「预算跑满主动收工」是**正常**、「撞墙熔断」是**异常**，两者此前共用同一个布尔值，日志与提示没法分开（现在主动收工不标红、也不说「完成」）。**顺带**：散在各处的 `new YuqueApi(...)`（`main.ts` / `ui.ts` 四处 / `sync.ts` / `backfill.ts`）统一收敛到 `plugin.createApi()`，观测回调只此一处注入；`package.json` 的版本号从 `0.1.0` 对齐到 `0.9.2`。**测试**：新增 `tests/rate.test.ts`（20 例：小时键、取数、跨小时归零、门槛取最小值、明细截断、建议预算 ×0.8、预算取更严者、脏数据迁移、响应头排序）与 4 例预算软停（不够则一篇不拉且零改动、够则正常完成、剩余额度优先、无需更新的库不被误伤），`npm test` **404 例全绿**；`npm run build` 类型检查通过。**同日实测补记（10:37）**：用户提供的 `GET /api/v2/user` 原始响应头把「双限流器」从推测变成**结论**——429 由边缘网关吐出（`Via: hz-crspanner-internet-prod-…[429]`）、链路为阿里云 WAF（`Set-Cookie: acw_tc=…`）、`X-OAuth-Scopes` 权限齐全（排除权限问题）、**无任何 `X-RateLimit-*`**、**单次请求即 429**（排除突发限流）、且 09:44 与 10:37 两次**跨过整点都未恢复**（推翻「按整点小时窗口重置」）。这份证据已固化为 `quota.ts` 的 `YUQUE_GATEWAY_LIMITER_EVIDENCE`，诊断文案从「更像网关层限流器」改为「已实测确认」，并新增一行解释**为什么没有配额头**（网关先拦，应用层没机会加头——这正是旧版那句写死的「语雀不提供配额头」错在哪）。由此得到一条对用户更重要的结论：网关惩罚态是**账号维度**的，生效期间官方那 5000 次/小时根本用不上，**「省着用」救不了它**——预算层能防的是「逼近应用层限额」，防不住这个；唯一能做的是把每次触发的累计请求数记下来，让门槛跨多次事件逐渐可测。仍未确定的只剩一项：**200 响应是否带 `X-RateLimit-*`**（决定动态预算分支能否用上），需等惩罚解除后再测。**验收中补的一项观测**：既然网关惩罚不在整点恢复，用户真正需要的是「这次惩罚已经持续多久」，于是 `RateLog` 增加 `lastAcceptedAt`（最近一次**未被网关拦截**的请求时间，`status 0` 的网络失败不算、429 本身也不算），把惩罚起点夹进「最后一次放行之后、首次 429 之前」的区间，诊断里直接给出「最近一次 429 距今 N 小时 M 分钟（起点在 … 之后、… 之前）」——这是目前唯一能估惩罚起点的线索。新增 3 条单测（`lastAcceptedAt` 只在被放行时刷新、摘要给出持续时长与起点区间、`describeRateLog` 支持注入 `now` 以免测试依赖真实时钟），`npm test` **406 例全绿**

- **v0.9.1** 修复「配额用尽时同步假卡死」。旧行为：429 走 5s/15s/30s 长退避（共 50s）才抛错，而 `syncTask` 的 `catch` 是通配的、捕获后**继续下一篇**——402 篇的库会变成约 5.6 小时纯空转，用户看到的只是「界面不动」，日志里还全是「拉取失败」。现在 429 先做一次 **2 秒短探测**：突发限流在这一步自愈，小时级配额不会，于是能在不误判的前提下区分两者；确认配额用尽即**熔断**——停止继续拉取（`YuqueQuotaError` + `isQuotaExhausted()`，不再与单篇失败混在一个 `catch` 里）、把已拉到的文档**照常写入并落盘记录**、明确提示「已同步 N 篇、剩余 M 篇」，配额恢复后再执行一次「立即同步全部任务」即从断点续跑（`syncTask` 只在写入成功后落 state，天然可续），日志也不再误报「完成」；`syncTask` 现在返回 `SyncTaskOutcome`，`syncAllTasks` 据此停掉后续任务，避免继续砸配额。**诊断命令**补上本次排查最缺的两项信息：`Token 权限范围`（响应头 `x-oauth-scopes`，被 429 拦下时语雀仍会返回，可据此直接排除「权限不足」这个误判方向）与 `限流层`（`via` 是否带 `[429]`，用于判断限流发生在网关层还是应用层），并区分 401/403/429 三种归因，遇 429 直接收尾不再刷屏。**配额口径收口**：实测语雀 429 既非 IP 限制、也非 UA 风控（同 IP 取页面 200、无 Token 请求 401）、更不是权限问题，而是**按 Token 维度的小时配额**，且**不返回** `Retry-After` 与 `X-RateLimit-*`，剩余量无从查询；因此新增 `src/yuque/quota.ts` 作为配额的**唯一真实来源**（实测出来之前是 `null`，工具链不再沿用传闻的 5000 下结论），`tools/census.ts` 的写死配额改为引用它，并新增 `tools/quota-ceiling.mjs`（连打 `/user` 直到 429，测出真实上限与窗口恢复时间）。新增 2 条回归测试：熔断后只尝试到失败那一篇、已拉到的照常落盘；以及对照项「普通单篇失败仍跳过继续，不被熔断误伤」

- **v0.7.1** 新增设置项**「在文件浏览器中隐藏图片文件夹」**（默认开启，位于「图片存放文件夹」下方）。动机：图片本地化会在每个同步任务的**目标文件夹之下**再建一层资源目录（默认 `assets`），它只服务于正文里的图片引用，在文件浏览器里却与文档混在一起，既占位置也打断阅读节奏。做法是运行时注入一段 CSS 把该条目隐去，而**不移动、不删除目录**——`![[assets/x.png]]` 是按 vault 路径解析的，与文件浏览器显不显示无关，所以正文图片照旧引用、照旧渲染，仓库结构一个字节都没变（这也是不选「把图片移到别处」的原因：那要连带改写所有正文里的图片路径，代价与风险都不成比例）。规则由新增的纯函数模块 `src/yuque/explorer.ts` 生成（`buildHiddenFolderCss`，10 个单测守着），要点有四：目录名**跟随设置项**「图片存放文件夹」，改名后规则同步变化；`data-path` 是**仓库相对完整路径**，因此同时匹配 `[data-path="assets"]`（根目录）与 `[data-path$="/assets"]`（任意子目录，`$=` 带斜杠所以 `myassets` 不会被误伤）；选择器**对新旧两套 DOM 结构都做了覆盖**（`.nav-folder-title` / `.nav-folder：has(...)` 与 `.tree-item-self` / `.tree-item:has(...)`，后者均限定在 `.workspace-leaf-content[data-type="file-explorer"]` 内，避免波及其它面板的列表）；除隐藏文件夹行外，还兜底隐藏紧随其后的子节点容器，这样 `:has()` 万一不可用也不会留下缩进的孤儿子项。边界照实说明：只是视觉隐藏，目录与图片仍在仓库里，搜索、快速切换、双链补全仍能命中（要让搜索也排除，可在 Obsidian「设置 → 文件与链接 → 排除的文件」里加上该目录名）；移动/拖拽文件时该目录同样不可见，需要往里面放图时先关掉开关

  同日补强（部署前自查发现的隐患）：最初只有 CSS 一条路，而 CSS 必须猜类名与容器属性，Obsidian 一改结构就会**静默失灵**——真出问题用户只会看到「没生效」，拿不到任何线索。于是加了第二条运行时路径：用工作区 API `getLeavesOfType("file-explorer")` 拿到文件浏览器视图的根节点，用 `MutationObserver` 盯住它的 DOM 变更（**挂在视图根节点而不是 `body`**：编辑器里每敲一个字都会改 DOM，挂 `body` 等于让扫描跟着输入跑），在视图内查带 `data-path` 的条目、按同一套路径规则打上 `yuque-hidden-folder` 类（该类对应的隐藏规则也写进注入的 `<style>`）。这一路只依赖 `data-path`（Obsidian 拖拽功能的基础，多年稳定），不认类名，换版本时明显更抗折腾；CSS 那份则退化成「纯样式也能兜住」的保险。两处易错点都做了防御：打标记时**只在「名字里带 children 的下一个兄弟」存在时才继续往里收**——文件行的下一个兄弟同样没有 `data-path`，若只按属性判断就会把同级的其它文件连锅端掉（这条专有 jsdom 用例守着）；关开关或改目录名时先清掉所有标记类，不留「幽灵隐藏」。命中数变化时往控制台打一行 `[yuque-style] 文件浏览器中命中 N 个「assets」条目（已隐藏）`，排查「隐藏没生效」先看这行：**命中 0 即说明 DOM 里没找到匹配条目**，结构与预期不符

- **v0.7.0** 修复「语雀端给知识库下的分组改名后，增量同步不会更新本地文件夹名」（v0.6.9 及以前一直如此）。根因：增量判定只比对文档自身的 `updated_at`，而分组（TOC 里的 TITLE 节点）改名**不会改动组内任何文档的这个字段**，于是整组命中「跳过未变化」，本地目录名永远停在旧的那个——文档正文没变，但目录结构已经变了。修法：同步记录新增 `folder` 字段存「上次同步时由 TOC 推出的分组」，每轮同步与本轮 TOC 比对，不一致就把文件整体搬到新分组下；**正文没变就不重新拉取**，只是移动文件。两个踩过的坑与两处防误伤：新增的分组目录必须先 `ensureFolder` 建好再 `vault.rename`（该 API 不会自动创建父目录，否则整组报 `ENOENT`——正是升级后第一次实测撞到的）；为了不与「用户自己在本地改目录名」冲突，`folder` 只记录**语雀侧**的分组（本地重命名走 `applyRename`，只改 `path` 不动它），并且只在「路径结尾确实对得上旧分组、且段边界落在 `/` 上」时才搬，对不上就尊重用户、原样不动；升级前写下的旧记录没有分组历史，先按当前本地结构认账并记下，所以**升级后第一次同步就撞上改名也能正确跟随**，不必白等一轮。配套：只有分组改名、一篇正文都不用写时，也会刷新「XX 目录.md」索引页（内容没变则不写，免得平白刷新文件时间）
