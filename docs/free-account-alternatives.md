> 目标问题：**不购买语雀会员，如何维持插件的原有功能？**

> ### ⚠️ 勘误二（2026-09-23 10:00，优先级同上）
> 下文 §2.2「配额可见性：**不可见**——无 `Retry-After`、无 `X-RateLimit-*`」这一行**结论过强**，
> 已被官方文档否定：语雀《[如何使用接口](https://www.yuque.com/yuque/developer/openapi)》明确记载
> **5000 次/小时、100 次/秒**，并称响应头会返回 `X-RateLimit-Limit` 与 `X-RateLimit-Remaining`。
> 复查当时的证据链：本仓库**只在一次 429 响应上**、且**只取三个头名**（`via` / `x-oauth-scopes` / `retry-after`）看过；
> `captureRate()` 从未读取配额头，全库也从未 dump 过完整响应头——所以「语雀不返回 `X-RateLimit-*`」
> 这个结论**从未被真正验证过**（v0.9.2 已把该断言从 UI 与 README 中移除，并补上完整头 dump）。
> 现在更准确的表述是：**429 响应上未见配额头**，且 429 由网关直接吐出（`via` 带 `[429]`）。
> 合理推断是**存在两个限流器**：应用层（官方记载、带配额头）与网关层（无契约、先拦截）；
> 后者能解释「≥8 小时不恢复」，前者不能。**裁决方式**：拿一次 **200 响应**的完整响应头看有没有配额头
> —— v0.9.2 的「诊断」已能打印，`src/yuque/rate.ts` 会把结果记进本地观测。
> 另注意官方更关键的一句：**「个人或团队下的所有 Token 共享同一个使用次数限制」**——
> 若该账号属团队空间且他人也在调用，额度会被持续重新烧掉，这比「未知超长窗口」更常见。

> ### ✅ 勘误三 / 裁决（2026-09-23 10:37，实测定论）
> 拿到的原始响应头（单次 `GET https://www.yuque.com/api/v2/user`）：
>
> ```
> STATUS 429
> Server: Spanner
> X-OAuth-Scopes: artboard,private_search,doc:read:detail,doc,repo,group
> Set-Cookie: aliyungf_tc=… ; acw_tc=781bad66…;path=/;HttpOnly;Max-Age=1800 ; …
> Via: hz-crspanner-internet-prod-ea133-9gffh-8ksvm[429]
> x-server-id / x-cchm: h:0,m:2 / x-readtime: 47   （无任何 X-RateLimit-*）
> ```
>
> **「双限流器」由此从推测变为结论**，且每一列证据都指向同一处：
>
> | 证据 | 排除/确认 |
> |---|---|
> | `Via: …[429]` | 429 由**边缘网关**吐出，不是应用层 |
> | `Set-Cookie: acw_tc=…` | 该边缘是**阿里云 WAF/CDN**（`acw_tc` 为防 CC 令牌） |
> | `X-OAuth-Scopes` 齐全 | ❌ 权限不足；鉴权**已通过** |
> | 无 `X-RateLimit-*` | 应用层的配额头**没机会加上**——不是「语雀不提供」（本文件 §2.2 与旧版 UI 的断言就此作废） |
> | **单次**请求即 429 | ❌ 突发限流（插件 400ms 节流远低于 100 次/秒）→ 是**账号被置于惩罚态** |
> | 09:44 与 10:37 均 429 | ❌ 按整点小时窗口重置（第一节勘误的「周期未定」再次被证实） |
>
> **推论（对本插件的直接后果）**：
> 1. 网关惩罚态是**账号维度**的（官方亦称所有 Token 共享同一限额），因此**换 Token 大概率无效**；
> 2. 惩罚态生效期间，官方那 5000 次/小时的**应用层额度根本用不上**——**「省着用」救不了它**，
>    只能等惩罚解除，或找出触发它的累计请求量；
> 3. 门槛只能**自己量**：`src/yuque/rate.ts` 的 429 时间线把每次触发的「当小时累计请求数」记下来，
>    取历次最小值作观测门槛（跨多次事件才收敛）；
> 4. 仍未确定的**唯一一项**：一次 **200 响应**是否带 `X-RateLimit-*`（要等惩罚解除后才能测），
>    它决定 0.9.2 的动态预算分支是否可用。目前「自动」预算在惩罚态下退化为 429 熔断 + 断点续跑。

## 〇、结论摘要

**原功能并没有因为"免费账户"而失效，因此也不需要替代认证方案。**

实测得到的真实结论与最初的假设相反：

1. **免费账户的 Token 权限是齐的。** 实测响应头 `x-oauth-scopes` 返回
   `artboard, private_search, doc:read:detail, doc, repo, group`，
   插件用到的 5 个只读端点**没有一个是会员专属**。所谓"免费账户被限制"，真身是**按 Token 维度的小时级配额已耗尽**。
2. **限流与 IP、UA、权限都无关。** 同一台机器取页面 200、无 Token 请求 401、带 Token 请求 429 —— 三个对照实验把"IP 风控""UA 被识别""权限不足"全部排除。
3. **语雀的配额是不透明的。** 429 由网关直接吐出（响应头 `via: ...-p42hn[429]`），且**不返回** `Retry-After`，也不返回任何 `X-RateLimit-*`。剩余额度**无法查询**，只能等小时窗口重置。
4. **真正在伤用户的不是配额，而是配额耗尽后插件的行为。** 旧实现把 429 当成"单篇失败"：每篇退避 50 秒后继续下一篇，402 篇的库约等于 **5.6 小时纯空转**，界面表现为"卡死"。这才是必须修的东西（已修，见第六节）。

因此，本次交付的核心不是"换一条认证通道"，而是**让插件在配额受限下可续、可预期**。

探针运行于 2026-09-23 凌晨，目标账号为一枚**免费账户**的个人访问令牌。

| # | 实验 | 结果 | 排除/确认的假设 |
|---|---|---|---|
| 1 | `GET /api/v2/user`（Token） | **429**，`via` 带 `[429]`，body `{"status":429,"message":"Too Many Requests"}` | 限流存在；且**无** `Retry-After` / `X-RateLimit-*` |
| 2 | 同 IP 取 `https://www.yuque.com/yuque/developer/api`（页面，无 Token） | **200** | ❌ 非 IP 级风控 |

| 4 | `GET /api/v2/user`（浏览器 UA + Token） | **429**（与实验 1 完全一致） | ❌ 非 UA 风控 |
| 5 | 检查实验 1 的响应头 | `x-oauth-scopes: artboard,private_search,doc:read:detail,doc,repo,group` | ✅ **Token 权限齐全**，429 与权限无关 |

## 二、免费账户 vs 会员：API 与令牌权限上的真实差异

### 2.1 差异一：**没有**权限差异（已实测）

| 维度 | 免费账户 | 会员账户 | 证据 |
|---|---|---|---|
| 能否创建个人访问令牌 | **能** | 能 | 实测该免费账号的 Token 正常工作并返回 scope |
| 可用的权限范围（scope） | `doc:read:detail`、`doc`、`repo`、`group`、`private_search`、`artboard` | 相同 | 实测 `x-oauth-scopes` 响应头 |
| 能否读取**私有**知识库 | **能**（前提：该账号本身是库成员/所有者） | 能 | 官方公告「Token 只可访问 Token 有权限的文档」——约束来自**成员身份**，与会员无关 |
| 本插件所需 5 个只读端点 | 全部可用 | 全部可用 | 端点均为公开 API v2 的标准只读接口 |

**官方依据**：语雀开发者文档《语雀开放 API 访问范围变更》（文档创建 2023-03-24，最近更新 2026-04-08）规定：
> 从 4.10 开始，所有个人 token 将只可访问 token 有权限的文档。

该公告把 Token 能力从"按账号身份大范围放权"改为"按 Token 实际被授予的权限"判定——**判定依据是权限，不是会员等级**。在可抓取的官方页面元数据中，**没有出现任何**将 API 权限与会员等级挂钩的说明。

### 2.2 差异二：**配额**（存在差异的说法未能证实，但限制确实存在）

| 维度 | 实测结论 |
|---|---|
| 限流维度 | **按 Token**（排除 IP 与 UA，见第一节实验 2/4） |
| 限流响应 | `429`，由网关吐出（`via` 带 `[429]`） |
| 配额可见性 | **不可见**：无 `Retry-After`、无 `X-RateLimit-*`，剩余量无从查询 |
| 恢复规律 | 按小时窗口重置（**具体数值待实测**，见第七节） |
| 免费 vs 会员的**具体数值差** | ⚠️ **未能证实**。官方 API 文档正文为 SPA 动态渲染，本次未能抓取到限流章节的权威数值；社区流传的"免费 5000 次/小时"**无官方出处** |

> 诚实标注：本仓库此前把传闻的 5000 写死在 `tools/census.ts` 里，并据此给"是否会超配额"的结论。这属于拿猜测当结论，已修正（现在配额写在 `src/yuque/quota.ts`，实测出来之前为 `null`，工具链对此明确报"未知"）。

### 2.3 差异三：会员真正买到的东西（与本插件无关）

按语雀产品页与社区口径，会员主要影响的是**语雀站内的内容容量与服务**，例如知识库/文档数量上限、附件与图片容量、历史版本、数据表/画板/小记的数量、公开分享、导出能力等。

对本插件而言：**这些差异都不构成阻塞**——插件只做"读取已有内容"，不创建、不上传、不搜索、不评论、不用画板、不用小记。

> 注意：2.3 一节的内容来自产品页与社区口径，**本次未逐条实测**，仅用于界定"哪些差异与插件无关"。若需要精确清单，应以语雀官方的版本对比页为准。

### 2.4 一个直接相关的官方能力：**批量导出对普通成员被锁**

- 语雀网页端的**单篇导出**（导出为 Markdown）可用。
- **批量导出**（整个知识库一次导出）按 2026-08 的社区实操记录，**对普通成员基本是锁着的**。

这条事实推翻了旧计划里"用官方导出包做冷启动"的设想：它**不是**一条可靠的免费批量通道。

## 三、官方与社区支持的"免费替代认证方式"全清单

| 通道 | 是否免费 | 技术可行性 | 限制与风险 | 结论 |
|---|---|---|---|---|
| **官方个人访问令牌（`X-Auth-Token`）** | ✅ 免费，无会员要求 | ✅ **当前正在用** | 受 Token 维度的小时配额约束；配额不透明 | ✅ **唯一正解** |
| **OAuth2（开放平台第三方应用）** | ⚠️ 疑似需申请资质 | ⚠️ 未核实 | 语雀开放平台在文档与社区中被提及提供 OAuth2（`client_id`/`client_secret` 换 `access_token`），但**个人开发者能否申请到未经核实**；即便拿到，`access_token` 与个人 Token **走同一限流域**，**不解决配额** | ❌ 不解决实际问题 |
| **Cookie 会话（`_yuque_session` + `yuque_ctoken`）** | ✅ 免费 | ⚠️ 可行但无契约 | 走网页端内部接口（`/api/...`），**无公开契约、可随时变更**；官方原话「系统识别异常行为后会进行屏蔽处理，**可能会导致用户不可用**」——**账号级封禁风险**；Cookie 明文存储；`ctoken` 轮换导致 403；其唯一潜在收益"换一个限流域"**未经证实** | ❌ 风险 > 收益 |
| **会话令牌 / CSRF token（ql-token 等）** | ✅ 免费 | ⚠️ 同 Cookie | 与 Cookie 属同一类非官方通道，风险与限制同上 | ❌ 同上 |
| **公开库匿名读取** | ✅ 免费 | ✅ 可行 | **只对公开知识库有效**；本插件目标库为**私有**，不适用 | ❌ 不适用 |
| **官方导出包导入** | ✅ 免费 | ⚠️ 受限 | **批量导出对普通成员被锁**，只有单篇导出 | ❌ 不可靠 |
| **社区工具导出的 Markdown（`yuque-exporter`、`M1r0ku/YuqueExport` 等）** | ✅ 免费 | ✅ 可行 | 本质是 Cookie 通道的第三方实现，**同样的 ToS 灰区与账号风险**；好处是**由用户自选、与插件解耦** | ⚠️ 可作插件外的**用户自选**旁路 |

**合规边界（本次决策）**：插件**不内置**任何非官方通道。理由：语雀官方明写异常行为"可能导致用户不可用"，而收益只是个未证实的降限流假设——一个要上 Obsidian 社区市场的插件不应拿用户的账号去赌这个假设。非官方通道交由**用户自选**的第三方工具承担，插件侧只在文档里做说明。

## 四、"若无法完全免费实现"时的替代工具与服务

先明确一件事：**本插件的原有功能不需要替代品**（第二节已论证）。以下是"如果将来配额成为硬瓶颈"时可用的手段，以及它们各自的合规判定。

| 手段 | 能解决什么 | 合规判定 | 是否采纳 |
|---|---|---|---|
| **本地缓存机制（同步记录 + 断点续跑）** | 配额耗尽后不重头再来；增量同步天然只在内容变化时拉取 | ✅ 完全合规（纯本地） | ✅ **已采纳**（`yuque_state` + 本次熔断修复） |
| **降低请求密度（节流 / 分窗口跑批）** | 把全量摊到多个小时窗口内完成 | ✅ 完全合规 | ✅ 已具备（400ms 节流）；是否需进一步压低取决于实测配额 |
| **图片按需下载** | 图片是请求量最大的一类（实测某 402 篇的库产出 4283 张） | ✅ 完全合规 | ⏸ 暂缓：功能优先，且已存在的图片不会重复请求 |
| **HTTP 响应缓存（TOC / 列表加 TTL）** | 省下每个库的固定开销 | ✅ 合规 | ❌ 不值得：13 个库仅省约 26 次请求，相对近 2000 篇的详情请求是 **1.3%** |
| **自建代理（缓存聚合、跨设备共享）** | 多设备复用一份缓存 | ✅ 合规 | ❌ 收益低：Obsidian Sync / git 已覆盖该场景 |
| **自建代理（多账号 Token 轮换池）** | 绕过单 Token 配额 | ❌ **违反服务条款**，且直接撞"账号不可用"红线 | ⛔ **明确排除** |
| **请求指纹伪装 / 抓包重放** | 规避风控 | ❌ **违反服务条款** | ⛔ **明确排除** |
| **语雀站内迁移到其它平台** | 从根本上脱离配额 | ✅ 合规 | ➖ 超出本插件范围 |

## 五、可操作的技术方案列表（含适用场景与限制）

按"投入产出比"排序。**方案 A 已实施**，B/C 视配额实测结果决定。

### 方案 A · 429 短探测熔断 + 断点续跑　【✅ 已实施】

| | |
|---|---|
| **做法** | 429 先做一次 **2 秒短探测**重试：突发限流此时已自愈，小时级配额不会——以此精准区分两者；确认配额耗尽即抛出专用错误 `YuqueQuotaError` 并**熔断**：停止继续拉取、把已拉到的文档照常写入并落盘、明确提示"已同步 N 篇、剩余 M 篇" |
| **适用场景** | 所有场景；**首次全量同步**与**大规模重跑**受益最大 |
| **限制条件** | 熔断后必须等语雀的小时窗口重置；插件无法预知剩余额度（语雀不提供该信息） |
| **替代了旧行为** | 旧行为：每篇退避 5s/15s/30s（共 50s）后继续下一篇 → 402 篇的库约 **5.6 小时**纯空转 |

### 方案 B · 预算制分批跑（每次同步最多 N 个请求）　【⏸ 条件触发】

| | |
|---|---|
| **做法** | 新增"每次同步最多消耗 N 个请求"的设置项，到点主动优雅停止并落盘，下次继续 |
| **适用场景** | 实测配额很低（例如 < 1000/小时）时，把首次全量变成可控的分批作业 |
| **限制条件** | 多一个设置项与一套预算逻辑（约半天工程量）；配额足够时纯属多余 |
| **触发条件** | 实测配额 **< 1000/小时** 才做 |

### 方案 C · 节流间隔自适应　【⏸ 条件触发】

| | |
|---|---|
| **做法** | 依实测配额把 400ms 节流调至合适值，使全量刚好落在窗口预算内 |
| **适用场景** | 实测配额中等（1000–3000/小时）时的低成本折中 |
| **限制条件** | 会拉长单次同步耗时；图片下载不受此约束（走 CDN，不占 API 配额） |
| **触发条件** | 实测配额 **1000–3000/小时** 时做（约 10 分钟工程量） |

### 方案 D · 插件外旁路（用户自选，不内置）　【➖ 不采纳】

| | |
|---|---|
| **做法** | 用户自行使用社区导出工具（`yuque-exporter` 等）把内容导出为本地 Markdown，再用别的方式并入 Obsidian |
| **适用场景** | 用户接受账号风险、且能自行承担后果时 |
| **限制条件** | 属语雀服务条款灰区，**有账号被限制的风险**；且导出物为 Markdown，会**丢失语雀样式语义**（Lake 结构、卡片块等），需要额外转换 |
| **为什么不内置** | 插件不应替用户承担 ToS 风险；且社区已有实现，重复造轮子无收益 |

## 附：核心判据速查

| 问题 | 答案 |
|---|---|
| 免费账户能用官方 API 吗？ | **能**，权限与会员无关（实测 scope 齐全） |
| 私有知识库能读吗？ | **能**，前提是该账号本身是库成员（与会员无关） |
| 需要买会员吗？ | **不需要**。插件用到的能力没有一项需要会员 |
| 需要 Cookie / OAuth 替代认证吗？ | **不需要**。Cookie 有账号风险且收益未证实；OAuth 不换限流域 |
| 那到底会卡在哪？ | **Token 维度的小时级配额**（不透明、不可查询、按小时窗口重置） |
| 卡住了怎么办？ | 插件会熔断并保存进度；窗口恢复后再执行一次「立即同步全部任务」即从断点续跑 |
